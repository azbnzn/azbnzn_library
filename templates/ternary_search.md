# 三分探索 (Ternary Search)

下に凸（または上に凸）な 1 峰性（ユニモーダル）関数の極値（最小値または最大値）を求める探索アルゴリズムです。

---

## 1. 概要・いつ使うか
- **計算量**:
  - 実数版: $O(\text{iter} \times f\text{の計算量})$ （100回のループで幅は $(2/3)^{100} \approx 2.4 \times 10^{-18}$ まで収束）
  - 整数版: $O(\log_{1.5}(R - L) \times f\text{の計算量})$
- **使える条件**: 探索区間において関数が**広義の単調減少 $\to$ 単調増加**（下に凸）または**単調増加 $\to$ 単調減少**（上に凸）であること。
- **典型問題**:
  - コスト関数や距離の最小化（例: 点 $(x, y)$ との距離、移動時間の最小化）
  - 数値シミュレーションのパラメータ最適化

---

## 2. コピペ用コード (C++)

### 1. 実数版 (下に凸・最小値探索)
```cpp
// [low, high] の区間から最小値をとる x を求める
double ternary_search_real(double low, double high, const function<double(double)>& f, int iter = 100) {
    for (int i = 0; i < iter; i++) {
        double m1 = low + (high - low) / 3.0;
        double m2 = high - (high - low) / 3.0;
        if (f(m1) < f(m2)) {
            high = m2; // 最小値は [low, m2] に存在
        } else {
            low = m1;  // 最小値は [m1, high] に存在
        }
    }
    return (low + high) / 2.0;
}
```

### 2. 整数版 (下に凸・最小値探索・安全設計)
```cpp
// [low, high] の区間から f(x) が最小となる整数 x を求める
ll ternary_search_int(ll low, ll high, const function<ll(ll)>& f) {
    while (high - low > 2) {
        ll m1 = low + (high - low) / 3;
        ll m2 = high - (high - low) / 3;
        if (f(m1) < f(m2)) {
            high = m2;
        } else {
            low = m1;
        }
    }
    // 区間幅が小さくなったら直接候補を評価してバグを防ぐ
    ll best_x = low;
    ll min_val = f(low);
    for (ll x = low + 1; x <= high; x++) {
        ll val = f(x);
        if (val < min_val) {
            min_val = val;
            best_x = x;
        }
    }
    return best_x;
}
```

---

## 3. 最大値（上に凸）を探したい場合
`f(m1) < f(m2)` の比較不等号を反転させて **`f(m1) > f(m2)`** にするか、評価関数の符号を反転（`-f(x)` を最小化）してください。

---

## 4. 注意点
1. **整数の三分探索の罠（無限ループ・境界バグ）**:
   - `high - low` が小さいときに `m1 == m2` になったり、区間が縮まらなくなるバグが多発します。
   - 上記のテンプレートのように `high - low > 2` の間だけ回し、**最後は残った数個の候補を線形探索で全チェックする構造**にすると絶対に境界バグが発生しません。
2. **プラトー（平坦な区間）の存在**:
   - 最小値付近で $f(x)$ の値が完全に平坦（横ばい）になっている区間がある場合、三分探索は正しく片側を切り捨てることができず失敗することがあります（厳密な単峰性が必要）。
3. **関数の評価が重い場合**:
   - 三分探索は 1 ステップあたり関数を 2 回評価します。関数の計算が重い場合は、後述の **黄金分割探索** を使うと評価回数を約 $40\%$ 削減できます。
